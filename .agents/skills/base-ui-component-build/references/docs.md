# Docs

The docs page proves the component works: every demo renders in the browser and doubles as a visual regression fixture.

## Files

- Page: `docs/data/material/components/<kebab-name>/<kebab-name>.md`.
- Demos: one folder per demo under `demos/`, in the three-file format described in `AGENTS.md` (Docs demos).
- Route: `docs/pages/material-ui/react-<kebab-name>.js`, copied from `react-number-field.js` with every `number-field` occurrence replaced.
- Navigation: an entry in `docs/data/material/pages.ts`, in the section of the closest existing component (a preview card next to `Tooltip`), with `newFeature: true`.
- API pages: generated by `pnpm docs:api` (`docs/pages/material-ui/api/*`, `docs/translations/api-docs/*`, and the entries in `docs/data/material/pagesApi.js`). Commit the generated files.

## Page front matter

```md
---
productId: material-ui
title: React Preview Card component
components: PreviewCard, PreviewCardTrigger, PreviewCardPopup
githubLabel: 'scope: preview card'
githubSource: packages/mui-material/src/PreviewCard
---
```

- `components` lists every public part, which links the page to each API page.
- Add `waiAria` only when an ARIA Authoring Practices pattern exists for the component.
- `githubLabel` may not exist yet; mention it in the PR description so a maintainer creates it.

## Page outline

1. Title, description, and `{{"component": "@mui/internal-core-docs/ComponentLinkHeader"}}`.
2. A basic demo, then one section per feature from the Base UI docs that the component exposes.
3. **Accessibility**: port every item of the Base UI "Usage guidelines" section, and say how to give the component an accessible name (`label`, or `aria-label` when there is no visible label). Add what the Base UI source shows but its docs leave out, such as a trigger that ignores touch input.
4. **Anatomy**: the parts and how they nest, as a `text` code block (Prettier rewrites comments inside a `jsx` block):

   ```text
   PreviewCard
   ├── PreviewCardTrigger
   └── PreviewCardPopup
   ```

5. **Customization**:
   - `render`: a short paragraph that says the part keeps its styles and that a render function receives the Base UI state. Add a demo only for a real use case, such as rendering a router link; a demo that swaps in an arbitrary element (`<aside>`) teaches nothing the API page does not.
   - `slots` and `slotProps`.
   - Theme `styleOverrides` and `variants`, with a live-state rule that uses the classes and data attribute constants.
   - Utility classes.
   - Data attributes: one list per part, each item naming the attribute and when it is present, taken from the Base UI `DataAttributes` JSDoc.

In page prose, write the brand names with a non-breaking space (`Material UI`, `Base UI`). Vale's `MUI.MuiBrandName` rule fails on a normal space. Code spans, code blocks, and link targets keep normal spaces.

## Demos

- Import each part from its subpath: `import PreviewCardTrigger from '@mui/material/PreviewCardTrigger';`.
- Standalone triggers always use `render`: `<PreviewCardTrigger render={<Button>Open</Button>} />`. Demos never pass `children` to a standalone trigger.
- Every `href` in a demo points at a heading anchor that exists on the page (`#detached-triggers`) or at an external URL. `pnpm docs:build` ends with a link check that fails the build on any other in-page anchor.
- Wrap the code readers should see in `// @focus-start` and `// @focus-end` comments; the `docs-infra/require-demo-focus` lint rule requires them.
- Pass an explicit `locale` to anything that formats numbers or dates, so the server and the browser render the same text.
- A demo that builds its own theme keeps the docs color mode: build it from the outer theme with `palette: { mode: outerTheme.palette.mode }` and `useTheme()`, as `CustomizedInputsStyleOverrides.tsx` does. A theme without it renders light text colors on the dark docs page.
- Document every default that differs from Base UI on the page, with both values ("8px by default, where Base UI defaults to 0").
- Keep demos short: inline the parts, use minimal `sx`, and use `component="p"` on `Typography` headings inside demos so the page keeps valid heading levels.

Done when each demo renders in `pnpm docs:dev` without console errors, and its interaction (open, select, type) works by hand or in a browser check.
